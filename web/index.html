SSD SoC — IP Closed-Loop Workflow

운영 모델: 8개 저장소 (RTL · Design · RDL · PG · HAL · Spec · FW · Test). 문서 작성 체인: Phase 1 RTL → Design → RDL → PG, Phase 2 Doc → HAL/FW/Test (Claude Code 작성+자체검증). FW 는 FPGA·Veloce·Zebu 에 load, Python coverif 는 SSD Host 에서 NVMe/PCIe 로 SoC 구동. 본 레포의 9-stage 흐름 (아래 §1) 은 그 운영 모델의 단일 저장소 개념 증명.

0. 운영 모델 — 8-repo 토폴로지 + Phase 1/2 + SSD Host coverif

실제 SSD Controller 개발은 8개 독립 저장소로 분리된다. 문서는 작성 의존 따라 Design (HLD+DLD) · RDL (SystemRDL) · PG (Programmer's Guide) 3개로, 코드는 HAL · FW · Test 3개로, 그리고 RTL · Spec 이 양 끝에. 펌웨어는 FPGA · Veloce · Zebu 에 binary 로 load 되어 실행되고, Python coverif 는 SSD Host (Linux 서버) 에서 NVMe/PCIe 로 그 펌웨어를 구동.

참조 위계: FW · Test (그리고 Claude) 는 PG/RDL primary → DLD fallback → RTL 직접 참조 금지. CI 의 P4/F3/T4 invariant 가 RTL 참조 코드를 PR 단계에서 자동 차단.

Hybrid 정합성 정책: 각 문서를 authored zone (사람 자유) + shadow zone (자동 sync, 수동 차단) 으로 분리. DLD §5 regmap · RDL register offset · HAL.h · PG §6 시그너처는 shadow → 사람 지식과 자동 정합성 동시 보존.

Claude Code = 개발자 + 자체 검증자: HAL.c · FW · Test 를 Claude 가 작성, PR 전 자기 출력물을 invariant 와 비교 (pre-PR self-check). CI 가 마지막 관문. 📘 §5 AI 자동화 · ▶ 슬라이드 7

1. 9-stage closed-loop — 개념 증명 (단일 저장소)

본 절부터의 9-stage workflow 는 위 §0 운영 모델의 single-repo 압축 형태이다. Programmer's Guide (Stage 5) 가 SW-HW 계약이며, scenarios (Stage 7) 가 그 계약을 RTL 검증으로 옮긴다. 운영에서는 Stage 6–8 이 FW Repo · Test Repo 로 분리되고, Stage 8 의 SV TB 는 FPGA/Veloce/Zebu + Python on SSD Host 로 대체된다.

4. 필요한 CI 시스템

저장소 9개 (8 repo + 1 release-gate) 각각이 자기 영역의 invariant 를 검사한다. GitHub Actions 기반.

Repo 워크플로우 주요 invariant / job runner
① RTL rtl-ci.yml Verible lint · Verilator smoke synth ubuntu-latest
② Design design-ci.yml RTL fetch · D1 shadow check · D2 shadow lock · D3 HLD↔DLD · D4 diagram render·diff ubuntu-latest
③ RDL rdl-ci.yml RTL fetch · R1 shadow check · R2 shadow lock · R3 peakrdl emit OK ubuntu-latest
④ PG pg-ci.yml Design+RDL submodule · P1 HAL.h↔§6 · P2 shadow lock · P4 RTL 직접 참조 금지 (regex) ubuntu-latest
⑤ HAL hal-ci.yml RDL submodule · H1 HAL.h=peakrdl(RDL) · H2 HAL.c↔HAL.h · H3 host smoke (make test) ubuntu-latest
⑥ Spec spec-ci.yml git LFS · S1 PDF↔MD pair check · S2 extract not stale ubuntu-latest + LFS
⑦ FW fw-ci.yml 5 submodule · F1 HAL 콜↔HAL.h · F2 submodule monotonic · F3 RTL #include 금지 (정적 분석) · F4 host smoke · F5 build (target toolchain) ubuntu-latest + cross-compiler
⑧ Test test-ci.yml 4 submodule · T1 Python↔§6 · T2 regress↔§8 · T4 RTL 참조 금지 · T5 pytest --collect-only ubuntu-latest + Python 3.11
Release release-gate.yml R1: FW · Test 의 5/4 doc submodule SHA 정렬 · R2: 9-tuple manifest 완결 ubuntu-latest
— coverif-nightly.yml FW binary load · Python scenario regress · metric/coverage 수집 self-hosted (FPGA / Veloce / Zebu 접근)

필요한 인프라

  • GitHub Actions — 본 표의 9 워크플로우 (PR-blocking required status check)
  • Self-hosted runners — FPGA·Veloce·Zebu 가 있는 lab 환경에 배치 (nightly coverif)
  • git LFS — Spec Repo 의 PDF · bitstream artifact 보관 (또는 S3)
  • Required Status Checks — main branch protection 에서 위 워크플로우 모두 required 로 표시
  • 알림 — Slack/email — release-gate fail 시 즉시 통보

5. 필요한 문서 변환 도구

현재 Word/Excel/PDF 산출물을 새 구조로 옮기기 위한 자동 변환 도구. 모두 OSS 위에 사내 후처리 1회 작성.

도구 입력 → 출력 저장소 OSS 기반
docx2md HLD/DLD .docx → .md ② Design pandoc + 사내 후처리 (헤딩 번호 보정, 표 정리, 이미지 추출)
xlsx2rdl SFR .xlsx → .rdl ③ RDL openpyxl + 자체 SystemRDL emitter (사내 Excel template 매핑)
pdf2md NVMe/PCIe/ONFI .pdf → 챕터별 .md ⑥ Spec pdftotext + 장/절 분리 + 표 후처리
peakrdl .rdl → IP-XACT XML · HAL.h · Markdown 표 ③→⑤ (RDL→HAL) peakrdl-ipxact, peakrdl-html, peakrdl-cheader
mermaid-cli .mmd source → SVG ② Design mermaid-cli (npm)
wavedrom-cli WaveDrom JSON → SVG ② Design wavedrom-cli (npm)
confluence-export Confluence 페이지 → Markdown ④ PG (initial) Confluence REST API + pandoc
shadow-lint @shadow:gen 주석 영역 수동 편집 감지 모든 doc CI 자체 (Python · git diff parse)

예시 명령

# 1) Word → Markdown (1 IP)
$ docx2md design-repo/nvme_ctrl/HLD.docx -o design-repo/nvme_ctrl/HLD.md
$ docx2md design-repo/nvme_ctrl/DLD.docx -o design-repo/nvme_ctrl/DLD.md

# 2) Excel → SystemRDL
$ xlsx2rdl --template enterprise excel/nvme_ctrl_sfr.xlsx \
           -o rdl-repo/nvme_ctrl/nvme_ctrl.rdl

# 3) SystemRDL → IP-XACT + HAL.h + regmap.md (한 번에)
$ peakrdl ipxact rdl-repo/nvme_ctrl/nvme_ctrl.rdl \
          -o rdl-repo/nvme_ctrl/nvme_ctrl.ipxact.xml
$ peakrdl c-header rdl-repo/nvme_ctrl/nvme_ctrl.rdl \
          -o hal-repo/include/nvme_ctrl_hal.h
$ peakrdl html rdl-repo/nvme_ctrl/nvme_ctrl.rdl \
          -o design-repo/nvme_ctrl/diagrams/regmap.md

# 4) PDF → Markdown (NVMe 2.0 표준)
$ pdf2md --split-chapter spec-repo/pdfs/nvme-2.0.pdf \
         -o spec-repo/extracted/nvme-2.0/

# 5) shadow zone 수동 편집 감지 (PR 단계 CI)
$ shadow-lint --check design-repo/nvme_ctrl/DLD.md
✓ §5 register map shadow zone in sync
✗ §5 register map shadow zone manually edited (lines 124-128) → PR blocked
