# 11. 결론 — 3가지 결정 요청

본 보고서는 10개의 장을 통해 다음 명제를 정당화했다:

> **마크다운 + Git + Submodule + RTL-Grounded CI** 워크플로우는
> SoC 산출물 관리의 **AI 시대 표준**이며, RAG/벡터DB/MCP 기반 검색
> 방식 대비 **정확성·비용·정합성·속도 모든 축에서 우월**하다.

이 결론은 우리만의 주장이 아니다:
- Anthropic Claude Code 팀이 자신들의 도구에서 같은 결정을 내렸다 (RAG → grep-first).[^1]
- DeepWiki/Devin이 "코드 옆에 사는 문서"를 향해 가고 있다 — 우리는 그 종착점에 서 있다.[^2]
- Diátaxis가 산업 표준 문서 프레임워크이며 docs-as-code와 결합된다.[^3]
- IEEE 1685-2022가 SFR 표준을 확정했다.[^4]
- NVIDIA·OSS 진영이 RTL LLM 학습 데이터로 잘 정돈된 git 산출물을 전제한다.[^5]

우리가 추가한 것은 **"이 6개 흐름을 한 워크플로우로 묶은 SoC 도메인 적용"
**이다.

---

## 11.1 임원/리더에게 요청하는 3가지 결정

### 결정 1 — 본 워크플로우를 **신규 IP/SoC의 표준**으로 채택
- 효과: Lane A (신규)는 즉시 효과 발생, 추가 인프라 비용 최소.
- 리스크: 낮음. 기존 산출물은 영향 없음.
- 기간: 즉시.

### 결정 2 — 활성 in-house IP의 **단계적 마이그레이션 승인** (Lane B)
- 효과: 12개월 내 활성 IP 100% 흡수. ROI는 8장 추정치 참조.
- 리스크: IP owner의 일시적 부담. 1 IP당 평균 1–2주.
- 기간: 6–12개월.

### 결정 3 — **PoC 측정 인프라 구축 승인** (KPI 대시보드)
- 효과: 산업 평균 수치를 사내 실측으로 대체. 6개월 시점 보고로 누적 효과 검증.
- 리스크: 거의 없음. 본 레포 `web/`의 확장만으로 가능.
- 기간: 2–3개월.

## 11.2 만약 채택하지 않으면 — 기회비용

| 시간이 흐름에 따라 | 채택 안 한 경우 |
|---|---|
| AI 코딩 도구 적용 시도 | 컨텍스트 부족으로 효과 50% 이하 머묾 (RAG 한계) |
| 신규 SoC 파생 | 사람의 산출물 복제·수정 비용 누적 |
| EDA 벤더 AI 도입 압력 | 락인된 솔루션 외 선택지 없음 |
| 외주 IP 흡수 | 포맷 비호환·정합성 격차 누적 |
| LLM Wiki / DeepWiki 류 확산 | 우리는 그 입력(잘 정돈된 git)을 만들어두지 못함 |

**가장 큰 기회비용은 인프라 비용이 아니라, 우리 SoC 산출물이 AI 시대의
입력으로 변환 가능한 상태로 정돈되지 못한다는 점**이다. 변환은 누적
비용이 되며, 시점이 늦어질수록 비용이 커진다.

## 11.4 마무리

> *"문서가 코드 옆에 살고, AI가 그 문서를 직접 읽고, CI가 그 정합성을
> 검사한다."*

이 한 문장이 본 보고서의 전부이다. 우리는 그 한 문장을 **실행 가능한
워크플로우 · 측정 가능한 KPI · 단계적 마이그레이션 · 산업 평균 근거**로
풀어냈다.

다음 보고서가 필요한 시점은 6개월 후의 **KPI 실측 회고**이다. 그때
우리는 산업 평균 수치 대신 사내 실측 데이터로 본 제안을 다시 검증할
것이다.
